1. System Overview & Architectural Synopsis
Cybersecurity Architecture
AI-Based Fake Identity & Document Screening System

DocSec AI is a modern, lightweight, and explainable document security screening platform engineered to triage identity documents against digital manipulation, fraudulent alterations, expired credentials, and generative synthetic anomalies. The system serves as an automated first-line triage tool for verification officers across financial KYC, academic admissions, employment verification, and public service compliance.

Unlike conventional monolithic deep learning systems that act as opaque "black boxes", DocSec AI operates on a defense-in-depth, explainable multi-checkpoint pipeline. By harmonizing deterministic optical rule parsing, cryptographic byte hashing, OpenCV visual forensics, and generative synthetic noise metrics, every flagged anomaly produces an itemized, defensible audit trail.

Core Architectural Pillars
  • Deterministic Explainability: No opaque hallucinations; every risk penalty links to concrete visual or syntactic evidence.
  • Cryptographic Integrity: SHA-256 byte hashing detects duplicate submissions and altered re-uploads.
  • Dual-Engine Forensics: Error Level Analysis (ELA) and Fourier noise profiling detect both Photoshop patches and AI diffusion synthesis.
  • Human-in-the-Loop Triage: Empowers analysts with a calibrated 0–100 risk score and actionable decision tiers.
Supported Credentials & Standards
  • Aadhaar Card: 12-digit UIDAI format syntax, QR layout anchors, and UIDAI typography parsing.
  • PAN Card: 10-character alphanumeric syntax (5 letters, 4 digits, 1 letter) & layout structure.
  • Driving License: State code regex, MoRTH schema, and date chronology validation.
  • Passport & Voter ID: Passport alpha-prefix syntax & EPIC 10-char alphanumeric schema.

2. Problem Statement & Threat Landscape
Security Threat Analysis
The Proliferation of Digital Document Forgery

In today's digital-first economy, customer onboarding and identity verification are predominantly conducted remotely through uploaded document scans. However, the democratization of powerful digital editing suites (Adobe Photoshop, GIMP, online canvas editors) alongside generative artificial intelligence (diffusion models, LLM document generation) has lowered the technical barrier to committing high-stakes document fraud.

Fraudsters routinely alter names, forge identification numbers, tamper with birth years to bypass age restrictions, or splice portrait photographs onto legitimate document templates. When presented to automated KYC portals or human reviewers, these fraudulent credentials frequently succeed because standard systems evaluate text in isolation without scrutinizing the underlying image pixels or compression physics.

Vulnerabilities in Existing Solutions
Cognitive Fatigue: Manual inspectors processing hundreds of scans daily miss micro-splicing and altered fonts.
Superficial OCR: Traditional text extractors confirm syntax but are completely blind to pixel recompression and digital pasting.
Black-Box Deep Learning: Opaque neural networks cannot produce explainable evidence for regulatory audits or customer appeals.
Non-ID Pollution: Systems waste computational resources running deep fraud checks on landscape photos, pet pictures, or blank pages.
3. Core Project Objectives
Engineering Milestones
01
Optical Extraction & Syntax

Reliably ingest multi-format documents (PDF, JPG, PNG) and extract critical identity fields (Name, ID Number, Dates) with regular expression validation and chronological integrity checks.

02
OpenCV Tampering Forensics

Deploy Error Level Analysis (ELA) at 90% recompression alongside bounding contour detection to expose JPEG recompression disparities, pasted patches, and edge gradient anomalies.

03
Generative AI Screening

Screen documents for generative synthetic indicators, including Fourier high-frequency noise variance, diffusion synthesis textures, and typographic baseline irregularities.

04
Cryptographic Integrity

Calculate deterministic SHA-256 cryptographic fingerprints on ingestion to immediately flag duplicate submissions, byte-level modifications, and session tamper attempts.

05
Explainable 0–100 Risk Score

Synthesize 8 independent checkpoint penalties into an explainable 0–100 calibrated risk score categorized into 3 actionable tiers (Likely Genuine, Requires Verification, Suspicious).

06
Security & Privacy Hardening

Enforce PBKDF2-SHA256 password hashing for analysts, parameterized SQLite queries against SQLi, 5MB file upload constraints, and strict HTTPOnly session protections.

4. End-to-End System Procedure Flowchart
1
Document Ingestion & Cryptographic Fingerprinting
Cryptographic Invariant

User submits document scan (JPG, JPEG, PNG, or PDF ≤ 5MB). The system immediately calculates the raw byte SHA-256 cryptographic digest and queries the SQLite fingerprints ledger to identify exact byte matches, duplicate submissions, or previous tampering records.

Input: Document File Algorithm: SHA-256 Hash Digest Output: 64-char Hex Fingerprint
2
Format Normalization & Canvas Preprocessing
PyMuPDF Engine

If input is a PDF, PyMuPDF (fitz) extracts embedded digital text streams and rasterizes Page 1 into a high-resolution 300-DPI RGB image. If input is a photo scan, OpenCV applies EXIF orientation normalization, scale standardization, and canvas color space alignment.

Input: PDF or Raster Image Engine: PyMuPDF + OpenCV Output: Standardized RGB Matrix
3
Image Quality Assessment & Optical Pre-Check
Checkpoints 1 & 2

Evaluates image sharpness using the Laplacian Focus Variance formula (σ2 ≥ 100 threshold). Assesses histogram brightness (under/over-exposure) and pixel resolution to ensure the image possesses sufficient optical clarity before security triage.

Metric: cv2.Laplacian() Variance Threshold: Sharpness > 100 Status: Passed / Low Quality
Gatekeeper Guardrail Checkpoint
Decision Gate: Is the Uploaded File a Valid Identity Document?

Evaluates document layout geometry, declared type anchors (Aadhaar, PAN, DL, Passport, Voter ID), textual keyword density, and aspect ratio. If the file is a landscape, pet photo, invoice, or screenshot without ID anchors, the gatekeeper rejects it immediately.

FALSE: Not an Identity Document Early Guardrail Exit

Document flagged as NOT_AN_ID, UNABLE_TO_IDENTIFY, or UNREADABLE. Risk score set to N/A (-1). Saved to audit trail with human review advisory.

Pipeline Halts • No False Fraud Accusation
TRUE: Valid Identity Document Confirmed Proceed to Forensics

Structural layout conforms to official Indian identity card specifications. Document proceeds directly to multi-engine optical extraction and dual forensic screening.

Proceeds to Checkpoint 4 • Deep Screening
4
Optical Character Extraction & Syntax Verification
Windows Media / Tesseract OCR

Multi-engine OCR parses alphanumeric characters across document coordinates. Regex syntax extractors isolate Document Number, Full Name, Date of Birth, Issue Date, and Expiry Date. Enforces chronological logic (e.g. Issue Date must precede Expiry Date; DOB must indicate age ≥ 18 and ≤ 120 years).

Regex Checks: Aadhaar (12-digit) • PAN (5L-4D-1L) • DL/Passport Chronology: Issue < Expiry • Valid DOB
5A
OpenCV Visual Tampering Forensics

Executes Error Level Analysis (ELA) by resaving the image at 90% JPEG compression and computing the absolute pixel disparity matrix:
ELA = |Original - Recompressed_90%| * Scale

Detects pasted patch bounding contours, edge gradient discontinuities, and mismatched noise ceilings around sensitive identity text fields.

Detects: Photoshop, Canva, Splicing, Digital Clones
5B
Generative AI & Synthetic Indicators

Inspects frequency domain characteristics using 2D Fast Fourier Transforms (FFT). Analyzes high-frequency residual distributions characteristic of diffusion synthesis and generative models.

Screens for typography kerning irregularities, baseline character jitter, and unnatural ultra-smooth synthetic background textures.

Detects: Midjourney, Stable Diffusion, DALL-E, Synthetics
6
Local Reference Registry Cross-Check
Demo SQLite Ledger

Cross-references extracted ID number and holder name against an academic demonstration registry. Academic Boundary: An unverified record incurs only a nominal +5 risk penalty (marking it "Requires Verification"), but never marks an ID as fraudulent or suspicious on its own.

Rule: Match = 0 pts Missing Record: +5 pts (Unverified, not fraud)
7
Multi-Factor Risk Calibration Engine (0–100 Scale)
Explainable Weighting

Synthesizes all 8 checkpoints into a deterministic, weighted risk score formula:

Score = Quality_Penalty(0-10) + Tampering_ELA(0-40) + AI_Synthetic(0-35) + Syntax_Inconsistency(0-20) + Registry_Missing(0-5)

Weights are clamped between 0 and 100 with clear evidence points explaining every added penalty.

8
3-Tier Risk Triage Classification & Action Protocol
Actionable Triage
LIKELY GENUINE
Score: 0 – 25

No significant visual manipulation, consistent typography, valid syntax, and clean ELA compression profile.

REQUIRES VERIFICATION
Score: 26 – 55

Unverified registry record, minor blur, missing optional fields, or expired validity date. Manual review recommended.

SUSPICIOUS DOCUMENT
Score: 56 – 100

Strong ELA compression disparity, pasted bounding contours, AI diffusion artifacts, or altered critical identifiers.

9
Forensic Audit Dossier & PDF Report Generation
Cryptographic Audit Trail

Generates a unique 8-character verification code, commits the audit record with SHA-256 fingerprint into SQLite, renders forensic ELA heatmap artifacts, and enables instant PDF report export for institutional compliance.

Deliverables: Interactive Dossier • Forensic Heatmaps • PDF Export • Audit Trail
