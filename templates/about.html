B.Tech CSE Cybersecurity Project Synopsis
Cybersecurity Platform
AI-Based Fake Identity & Document Screening System

A lightweight, robust web-based document security screening platform designed to assist verification officers in screening identity documents for signs of digital alteration, expiration, syntax irregularities, and synthetic registry mismatches using transparent rule-based logic and computer vision forensics.

Core Objectives
  • Extract text fields using optical character recognition (OCR).
  • Screen for visual alteration anomalies with OpenCV.
  • Track document file modifications via SHA-256 integrity checks.
  • Calculate an explainable 0–100 risk score without opaque black-box ML.
Security Best Practices
  • PBKDF2-SHA256 password hashing for analyst authentication.
  • MIME-type & 5MB file-size upload restriction.
  • Parameterized SQLite queries to prevent SQL Injection.
  • HTTPOnly session cookies and secure headers.
The 8 Independent Screening Checkpoints
Pipeline Architecture
Checkpoint 1: Image Quality & Sharpness

Evaluates Laplacian focus variance, resolution thresholds, and optical contrast to verify scan adequacy before security analysis.

Checkpoint 2: OCR & Information Extraction

Extracts identity fields (Name, ID Number, Dates) using regex syntax parsing and confidence estimation.

Checkpoint 3: Field Consistency

Validates date chronology (e.g. Issue Date before Expiry Date, valid DOB) and document syntax patterns.

Checkpoint 4: Document Structure

Verifies expected structural components, layout margins, and field completeness conforming to document type.

Checkpoint 5: Alteration Indicators (OpenCV)

Screens for copy-paste splicing, overlaid rectangular bounding boxes, and Error Level Analysis (ELA) recompression disparity.

Checkpoint 6: AI / Synthetic Indicators

Analyzes diffusion generation noise, baseline typography jitter, and generative synthetic patterns.

Checkpoint 7: Record Match (Local Demo Registry)

Cross-references a synthetic reference registry. Clarification: Absence of record indicates unverified status, NOT automatic fraud.

Checkpoint 8: File Integrity (SHA-256 Digest)

Tracks cryptographic hash of document bytes to detect modified re-uploads across screening sessions.

System Boundaries & Technical Disclaimer
  • Preliminary Screening Prototype: This tool is engineered to triage and flag anomalies; it does not claim to definitively prove document authenticity.
  • Local Demo Registry: Contains synthetic SQLite records for academic demonstrations. It does not access real government, law enforcement, or official identity databases.
  • SHA-256 Cryptographic Fingerprint: Tracks file tampering relative to previously stored files, but does not prove original document authenticity.
  • Human-in-the-Loop: Final verification decisions should always be confirmed through authorized manual or primary issuing authorities.
College Viva Cheat Sheet
Quick Q&A
Q1: How does SHA-256 hashing help? It generates a unique cryptographic fingerprint of document bytes. If a user modifies even a single pixel or text digit and re-uploads, the hash changes completely. It verifies byte integrity, not original authenticity.
Q2: How does OpenCV detect tampering? Through Error Level Analysis (ELA) which highlights JPEG recompression differences between pasted patches and the original document background, plus contour box detection.
Q3: Why 3 calibrated risk tiers? 0–25 (Likely Genuine): No significant anomalies.
26–55 (Requires Verification): Unverified registry record or expired dates.
56–100 (Suspicious): Strong tampering or AI generative artifacts.
Q4: Why transparent rule-based logic? In high-stakes security, black-box deep learning models produce unexplainable hallucinations. Rule-based forensic scoring gives exact reasons for every flag.
Q5: What if the database record is missing? Missing registry match contributes +5 risk points (marking it Requires Verification), but NEVER marks it as Suspicious or Fake by itself.
