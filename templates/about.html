College Project Synopsis
B.Tech CSE (Cybersecurity)
AI-Based Fake Identity & Document Screening System

A lightweight, professional web-based document security screening platform designed to assist verification officers in screening identity documents for signs of digital alteration, expiration, syntax irregularities, and synthetic registry mismatches using transparent rule-based logic and computer vision.

Core Objectives
  • Extract text fields using optical character recognition (OCR).
  • Screen for visual alteration anomalies with OpenCV.
  • Track document file modifications via SHA-256 integrity checks.
  • Calculate an explainable 0–100 risk score without black-box ML.
Security Best Practices
  • PBKDF2-SHA256 password hashing for analysts.
  • MIME-type & 5MB file-size upload restriction.
  • Parameterized SQLite queries to prevent SQL Injection.
  • HTTPOnly session cookies.
The 5-Stage Screening Pipeline
Stage 1: Document Integrity Check (SHA-256)

Computes a 256-bit cryptographic digest of the ingested file. Detects if an identical file was re-uploaded or if a document with the same ID has different bytes.

Stage 2: Optical Character Recognition (Tesseract)

Scans the document image for text strings, extracting fields such as Name, Document ID, Date of Birth, and Expiry Date using regular expression matching.

Stage 3: Logical Format & Registry Validation

Verifies document dates against current timestamp, checks ID syntax patterns, and cross-references a synthetic SQLite registry of authorized sample records.

Stage 4: Computer Vision Alteration Screening (OpenCV)

Analyzes image noise gradients, blur variance (Laplacian method), and compression edges to identify copy-paste splices and digital modifications.

Stage 5: Explainable Risk Scoring Engine (0–100)

Consolidates all check findings into a transparent 0–100 score: Low Risk (0–30), Medium Risk (31–60), and High Risk (61–100), accompanied by clear human-readable justifications.

System Boundaries & Technical Disclaimer
  • Preliminary Screening Prototype: This tool is engineered to triage and flag anomalies; it does not claim to definitively prove document authenticity.
  • OCR Imperfections: Tesseract performance depends on scan resolution, lighting glare, and font irregularities.
  • Synthetic Testing Data: All sample records, names, and numbers are fictional. No real personal identifiable information (PII) is used.
  • Human-in-the-Loop: Final verification decisions should always be performed through an authorized manual or official verification authority.
Viva Voce Cheat Sheet

Complex deep learning models operate as black boxes where decisions cannot be audited or explained. A rule-based scoring engine provides 100% transparency for every deducted point during security inspections.

When an image is ingested, its raw binary bytes are processed through SHA-256 to generate a 64-character hexadecimal digest. Due to the avalanche effect, altering even a single pixel completely alters the hash.

We calculate the variance of the Laplacian filter to measure focus and sharpness consistency, check quadrant variance ratios to spot pasted text patches, and perform Error Level Analysis (ELA) for compression disparity.

All database queries utilize parameterized SQL statements with ? placeholders, completely preventing SQL injection vulnerabilities. Analyst passwords are salted and hashed using PBKDF2.
